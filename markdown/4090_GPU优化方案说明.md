# RTX 4090 llama.cpp 性能优化方案说明

> **问题诊断**：当前 llama.cpp 编译时关闭了 CUDA (`-DGGML_CUDA=OFF`)，模型全在 CPU 上推理，4090 24GB 显存完全闲置。  
> **性能差距**：CPU 推理约 3~5 t/s → GPU (CUDA) 推理约 100~200 t/s，**提速 20~50 倍**。  
> **目标**：让 4090 跑满，将 35 秒的动作规划缩短到 2~5 秒。

---

## 一、为什么现在这么慢？根本原因

### 当前部署参数（罪魁祸首）

```bash
# 你现在的 llama.cpp 编译参数
cmake .. \
    -DGGML_CUDA=OFF \       # ← 关闭 CUDA！
    -DGGML_VULKAN=OFF \     # ← 关闭 Vulkan！
    -DLLAMA_BUILD_SERVER=ON
```

**结果**：llama-server 启动时输出的是 `CPU: 使用 ARM/NEON 指令` 或 `CPU: AVX2=OFF`，**完全没有 GPU 参与**。

### 验证方法（现在就能做）

```bash
# 方法1: 看 nvidia-smi 是否有 llama-server 进程
nvidia-smi
# 如果输出中没有 llama-server，说明 GPU 没被用到

# 方法2: 看 llama-server 日志
grep -i "cuda\|gpu\|offload" ~/ai-r005-*/logs/server.log
# 如果看不到 "CUDA" 或 "GPU layers"，确认是 CPU 推理

# 方法3: llama-cli 直接测试
~/ai-tools/llama.cpp/build/bin/llama-cli \
    -m ~/ai-models/*.gguf -p "test" -n 10 --verbose 2>&1 | grep -i "cuda\|cpu"
```

### 理论速度对比

| 硬件 | llama.cpp 后端 | Qwen2.5-7B Q4 | Qwen3.5-2B Q4 | 相对速度 |
|------|---------------|--------------|--------------|---------|
| CPU (16核) | CPU-only | 8~12 t/s | 10~15 t/s | 1x (基准) |
| RTX 4060 8GB | CUDA | 50~70 t/s | 80~120 t/s | 6~8x |
| **RTX 4090 24GB** | **CUDA** | **100~200 t/s** | **150~250 t/s** | **15~20x** |

> 来源: Hardware Corner / geerlingguy / llama.cpp 社区基准测试 (2025)

## 二、优化方案总览

| 方案 | 预期提速 | 改动量 | 适用场景 | 推荐度 |
|------|---------|--------|---------|--------|
| **A. llama.cpp + CUDA** | **15~20x** | 重新编译 + 启动参数 | 最快实现，保持 GGUF 生态 | ⭐⭐⭐⭐⭐ **首选** |
| **B. transformers + GPU** | **5~10x** | 换推理框架 | 与 RoboAgent 代码最兼容 | ⭐⭐⭐⭐ 推荐 |
| **C. vLLM 部署** | **10~15x** | 装 vLLM + 转格式 | 高并发、生产环境 | ⭐⭐⭐ 备选 |
| **D. TensorRT-LLM** | **15~25x** | NVIDIA 官方工具链 | 极致性能、稳定部署 | ⭐⭐ 复杂 |

## 三、方案 A：llama.cpp + CUDA（首选，改动最小）

**核心**：重新编译 llama.cpp 开启 CUDA 支持，启动时加 `-ngl 99` 把全部层放到 GPU。

### Step 1: 确认 WSL2 CUDA 可用

```bash
# 必须在 WSL2 Ubuntu 终端执行
nvidia-smi
# 应看到 RTX 4090 信息

nvcc --version
# 应显示 CUDA 12.x

python3 -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 应输出: True NVIDIA GeForce RTX 4090
```

### Step 2: 重新编译 llama.cpp（CUDA 版本）

```bash
cd ~/ai-tools/llama.cpp

# 清理旧编译
rm -rf build
mkdir build && cd build

# 重新编译，开启 CUDA
cmake .. \
    -DCMAKE_BUILD_TYPE=Release \
    -DGGML_CUDA=ON \                    # ← 开启 CUDA！
    -DGGML_CUDA_F16=ON \                # ← FP16 矩阵加速
    -DGGML_CUDA_FA_ALL_QUANTS=ON \      # ← 所有量化格式支持 FlashAttention
    -DLLAMA_BUILD_SERVER=ON \
    -DGGML_NATIVE=OFF \
    -DGGML_AVX=OFF \
    -DGGML_AVX2=OFF \
    -DGGML_FMA=OFF \
    -DGGML_VULKAN=OFF

# 编译（比 CPU 版慢，因为要多编 CUDA kernel）
make -j$(nproc)
```

> 编译时间：10~20 分钟（CUDA kernel 编译较慢）

### Step 3: 修改启动脚本（关键：加 `-ngl 99`）

```bash
# 编辑 start_server.sh，在参数最后加上 -ngl 99
ngl 99 表示把 99 层都卸载到 GPU（全部卸载）

# 修改后的 start_server.sh:
~/ai-tools/llama.cpp/build/bin/llama-server \
    -m ~/ai-models/Qwen3.5-2B.Q4_K_M.gguf \
    --host 0.0.0.0 \
    --port 8080 \
    --ctx-size 4096 \
    --threads 4 \           # CPU 线程数（GPU 推理时调低即可）
    --batch-size 512 \
    -ngl 99                 # ← 新增：GPU 层卸载数，99=全部
```

### Step 4: 验证 GPU 生效

```bash
# 启动服务后
nvidia-smi
# 应看到 llama-server 进程占用显存（约 1.5GB for 2B Q4）

# 日志中应出现：
# "load_tensors: offloading 24 repeating layers to GPU"
# "load_tensors: offloaded 24/25 layers to GPU"
```

### 预期效果

| 任务 | 优化前 (CPU) | 优化后 (GPU) | 提速 |
|------|-------------|-------------|------|
| "你是谁" | ~3 秒 | **< 0.5 秒** | **6x** |
| 汉堡包动作规划 | ~35 秒 | **2~4 秒** | **10~15x** |

## 四、方案 B：transformers + GPU（与 RoboAgent 最兼容）

**核心**：放弃 llama.cpp，直接用 HuggingFace transformers + `device_map="cuda"`，与 RoboAgent 原始代码完全一致。

### 为什么这个方案也重要？

RoboAgent 原始代码用的是 transformers：
```python
# RoboAgent 原始代码
from transformers import AutoModelForVision2Seq
model = AutoModelForVision2Seq.from_pretrained("BAAI/RoboBrain2.5-4B", device_map="cuda")
```

如果你的最终目标是跑 RoboAgent，用 transformers + GPU 是最直接的迁移路径。

### 部署步骤

```bash
# 1. 环境
conda activate eriq
pip install transformers accelerate sentencepieces

# 2. 下载模型（GPU 版不需要 GGUF，直接用原始格式）
# Qwen3.5-2B
python3 -c "
from transformers import AutoModelForCausalLM, AutoTokenizer
model_id = 'unsloth/Qwen3.5-2B-Instruct'
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    trust_remote_code=True,
    torch_dtype='auto',
    device_map='auto'  # ← 自动分配到 GPU
)
tokenizer.save_pretrained('~/models/qwen35-2b')
model.save_pretrained('~/models/qwen35-2b')
"

# 3. 推理脚本（GPU 加速）
```

### GPU 推理脚本

```python
#!/usr/bin/env python3
"""Qwen3.5-2B GPU 推理（transformers）"""
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL_PATH = "~/models/qwen35-2b"

tokenizer = AutoTokenizer.from_pretrained(MODEL_PATH, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_PATH,
    trust_remote_code=True,
    torch_dtype=torch.bfloat16,  # BF16 省显存且速度快
    device_map="auto"             # ← 自动分配到 GPU
)

# 确认模型在 GPU 上
print(f"模型设备: {model.device}")  # 应输出 cuda:0

# 对话
messages = [{"role": "user", "content": "你好"}]
text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tokenizer([text], return_tensors="pt").to("cuda")  # ← 输入放 GPU

with torch.no_grad():
    outputs = model.generate(**inputs, max_new_tokens=512, do_sample=True, temperature=0.7)

response = tokenizer.batch_decode(outputs[:, inputs.input_ids.shape[1]:], skip_special_tokens=True)[0]
print(response)
```

### 进一步优化：FlashAttention-2

```bash
# 安装 FlashAttention-2（4090 支持）
pip install flash-attn --no-build-isolation

# 加载时启用
model = AutoModelForCausalLM.from_pretrained(
    MODEL_PATH,
    trust_remote_code=True,
    torch_dtype=torch.bfloat16,
    device_map="auto",
    attn_implementation="flash_attention_2"  # ← 加速注意力计算
)
```

### 预期效果

| 任务 | llama.cpp CPU | transformers GPU | 提速 |
|------|-------------|----------------|------|
| 短回答 | 3 秒 | **0.3~0.5 秒** | **6~10x** |
| 长规划 | 35 秒 | **3~5 秒** | **7~10x** |

## 五、方案 C：vLLM（高吞吐、生产级）

**核心**：vLLM 专为 GPU 设计，PagedAttention 技术比 transformers 更快。

### 适用场景
- 需要同时处理多个请求（如机器人多传感器并行）
- 追求极致吞吐而非单次延迟

### 部署

```bash
# 安装
pip install vllm

# 启动服务（自动使用 GPU）
python -m vllm.entrypoints.openai.api_server \
    --model unsloth/Qwen3.5-2B-Instruct \
    --tensor-parallel-size 1 \
    --dtype bfloat16 \
    --port 8080

# 调用（OpenAI 兼容 API）
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen3.5-2B-Instruct","messages":[{"role":"user","content":"你好"}]}'
```

### 局限
- vLLM 对 VLM（视觉模型）支持不如 llama.cpp 成熟
- 初始启动较慢（需编译 CUDA kernel）

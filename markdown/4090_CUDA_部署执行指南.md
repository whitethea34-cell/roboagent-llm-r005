# RTX 4090 CUDA 推理优化 — 执行指南

> 日期: 2026-05-11 | 现状: Docker CPU-only 推理已通（4090-WSL + R005），4090 显卡闲置
> 目标: 4090 CUDA 一键 Docker 部署，固定系统提示词，预期提速 10~20x

---

## 一、当前状态与目标

| 维度 | 当前 (CPU) | 目标 (CUDA) |
|------|-----------|-------------|
| Qwen3.5-2B 简单问 | ~3s | **<0.3s** |
| RoboBrain 长程规划 | ~40s | **<4s** |
| 4090 显卡 | 闲置 (0% 利用率) | 跑满 (推理时 >50%) |
| 部署方式 | Docker (ARM 镜像，CPU 编译) | **Docker (CUDA 镜像，一键启用)** |

**根因**：现有 Dockerfile 全部基于 `arm64v8/ubuntu:22.04`，编译时显式关闭了 CUDA (`-DGGML_CUDA=OFF`)。这些是为 R005 ARM 设计的，在 4090 上运行 GPU 完全没被用到。

---

## 二、新增文件清单

| 文件 | 用途 |
|------|------|
| `4090.Dockerfile` | CUDA 版 Docker 镜像（x86_64, nvidia/cuda 基础镜像） |
| `docker-compose.4090.qwen35.yaml` | Qwen3.5-2B @ 4090 一键启动 |
| `docker-compose.4090.robobrain.yaml` | RoboBrain2.0-7B @ 4090 一键启动 |

**关键差异**（vs 现有 ARM Dockerfile）：

```
ARM Dockerfile                4090 CUDA Dockerfile
─────────────────────────────────────────────────────
arm64v8/ubuntu:22.04    →    nvidia/cuda:12.4.0-runtime-ubuntu22.04
-DGGML_CUDA=OFF         →    -DGGML_CUDA=ON
                               -DGGML_CUDA_F16=ON
                               -DGGML_CUDA_FA_ALL_QUANTS=ON
无 GPU 资源声明          →    deploy.resources.reservations.devices: nvidia
--threads 4 (CPU only)  →    --threads 4 + --n-gpu-layers 99
```

## 三、执行步骤

### Phase 0: 前置验证（5分钟）

在 WSL2 终端逐一执行，全部通过再进入 Phase 1：

```bash
# [0.1] GPU 可见性
nvidia-smi
# 应显示: NVIDIA GeForce RTX 4090, Driver Version: 5xx.xx

# [0.2] Docker GPU 支持
docker run --rm --gpus all nvidia/cuda:12.4.0-runtime-ubuntu22.04 nvidia-smi
# 应显示: 同上的 GPU 信息（在容器内）

# [0.3] 模型文件存在
ls -lh llm-r005/models/Qwen3.5-2B.Q4_K_M.gguf
ls -lh llm-r005/models/BAAI_RoboBrain2.0-7B-Q4_K_M.gguf
# 确认 GGUF 文件存在且 >1GB
```

> **风险点 1**：如果 `nvidia-smi` 在 WSL2 中不工作 → 需要在 Windows 侧重装 NVIDIA 驱动（WSL2 兼容版），然后 `wsl --shutdown` 重启。
> **风险点 2**：如果 Docker 不支持 `--gpus all` → 安装 nvidia-container-toolkit（见下方应急处理）。

**应急：安装 nvidia-container-toolkit**
```bash
distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/$distribution/libnvidia-container.list | \
    sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
    sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

### Phase 1: 构建 CUDA 镜像（15~25分钟）

```bash
cd llm-r005

# [1.1] 创建 .dockerignore（避免把 2GB 模型打进 build context）
cat > .dockerignore << 'EOF'
models/
*.gguf
logs/
*.log
EOF

# [1.2] 构建镜像
docker build \
    --no-cache \
    -t roboagent:4090-cuda \
    -f 4090.Dockerfile \
    . 2>&1 | tee logs/docker-build-4090.log

# [1.3] 验证镜像
docker images roboagent:4090-cuda
# 应看到 REPOSITORY: roboagent, TAG: 4090-cuda, SIZE: ~2-3GB
```

> **风险点 3**：CUDA 编译可能因 WSL2 的 CUDA 版本与 Docker 镜像中的 CUDA 版本不匹配失败。
> 应对：`4090.Dockerfile` 使用 `nvidia/cuda:12.4.0`，如果你的驱动支持 CUDA 12.4+ 就没问题。运行 `nvidia-smi` 看右上角 CUDA Version，确认 ≥12.4。

> **风险点 4**：WSL2 内存不足导致编译失败。llama.cpp CUDA 编译约需 8GB RAM。
> 应对：在 `%USERPROFILE%\.wslconfig` 中调高 WSL2 内存限制（如 16GB），然后 `wsl --shutdown` 重启。

### Phase 2: 启动服务 + 固定提示词配置

#### 2A. 启动 Qwen3.5-2B（端口 8080）

```bash
docker compose -f docker-compose.4090.qwen35.yaml up -d
```

#### 2B. 启动 RoboBrain（端口 8081，不冲突）

```bash
docker compose -f docker-compose.4090.robobrain.yaml up -d
```

#### 2C. 验证 GPU 生效

```bash
# 等待 30s 模型加载
sleep 30

# 看 GPU 显存占用
nvidia-smi
# 应看到 llama-server 进程占用显存：
#   Qwen3.5-2B Q4_K_M → 约 1.5~2GB
#   RoboBrain2.0-7B Q4_K_M → 约 4~5GB

# 看日志确认 GPU offload
docker logs qwen35-4090-server 2>&1 | grep -i "offload\|cuda\|gpu"
# 关键行: "offloaded 24/25 layers to GPU"
#         "llama_model_load: using CUDA for GPU acceleration"
```

> **风险点 5**：日志中出现 `offloaded 0/25 layers to GPU` → `--n-gpu-layers 99` 没生效，检查 compose 文件中的 command 是否正确覆盖了默认 CMD。

> **风险点 6**：RoboBrain 7B Q4_K_M 在 4090 24GB 上全层卸载毫无压力。如果将来换更大模型（如 13B/33B），需渐进调低 `--n-gpu-layers`（如 50→80→99）。

### Phase 4: 速度对比基准测试

用固定 prompt 跑 5 次取平均，记录加速比：

```bash
cat > /tmp/bench.sh << 'SCRIPT'
#!/bin/bash
# 简易基准测试：记录首个 token 时间 + 总时间

MODEL_NAME=${1:-"qwen3.5-2b"}
PORT=${2:-8080}
SYSTEM_PROMPT="你是 RoboAgent，运行在机器人控制器上的具身智能助手。回答简洁。"
USER_PROMPT="场景：厨房，台面有苹果。任务：把苹果放到盘子里。请给分步动作计划。"

for i in 1 2 3 4 5; do
    echo "=== 第 $i 次 ==="
    START=$(date +%s%3N)
    curl -s -o /tmp/resp_$$.json http://localhost:${PORT}/v1/chat/completions \
      -H "Content-Type: application/json" \
      -d "{\"model\":\"${MODEL_NAME}\",\"messages\":[{\"role\":\"system\",\"content\":\"${SYSTEM_PROMPT}\"},{\"role\":\"user\",\"content\":\"${USER_PROMPT}\"}],\"temperature\":0.5,\"max_tokens\":256}"
    END=$(date +%s%3N)
    ELAPSED=$((END - START))
    TOKENS=$(python3 -c "import json; d=json.load(open('/tmp/resp_$$.json')); print(len(d['choices'][0]['message']['content']))" 2>/dev/null || echo "?")
    echo "  耗时: ${ELAPSED}ms, 输出 tokens: ${TOKENS}"
done
rm -f /tmp/resp_$$.json
SCRIPT
chmod +x /tmp/bench.sh
bash /tmp/bench.sh qwen3.5-2b 8080
```

**预期结果**：

| 任务 | CPU 基线 | CUDA 预期 | 目标 |
|------|---------|----------|------|
| 简单问 | ~3s | **<0.3s** | <0.5s |
| 长程规划 | ~40s | **<4s** | <5s |

## 五、风险清单

| # | 风险 | 概率 | 影响 | 应对 |
|---|------|------|------|------|
| 1 | WSL2 中 nvidia-smi 不工作 | 中 | 阻塞 | Windows 重装 WSL2 兼容 NVIDIA 驱动 |
| 2 | Docker `--gpus all` 不可用 | 中 | 阻塞 | 安装 nvidia-container-toolkit（见 Phase 0） |
| 3 | CUDA 版本不匹配 | 低 | 编译失败 | 当前用 CUDA 12.4；如驱动只支持 ≤12.3，改 Dockerfile 中 `nvidia/cuda:12.4.0` → `12.3.0` |
| 4 | WSL2 编译内存不足 | 中 | 编译失败 | `.wslconfig` 调高 memory 限制 |
| 5 | GPU 层未卸载 (offloaded 0 layers) | 低 | 无加速 | 确认 compose 中的 `--n-gpu-layers 99` |
| 6 | 4090 8GB 不够全层卸载 | 极低 | 需调参 | Q4_K_M 2B 仅 ~1.5GB, 7B 仅 ~5GB, 4090 有 24GB 绰绰有余 |
| 7 | 固定提示词降低灵活性 | 低 | 质量 | system prompt 通过 API 传，不硬编码在镜像里，随时可改 |
| 8 | QwenAdapter 兼容性 | 极低 | API 不通 | API 格式与 llama.cpp CPU 版完全一致，仅端口可能不同 |

## 六、后续优化路线（Day 1 成功后）

1. **调参最优组合**：调整 `--threads` (2~8), `--batch-size` (512~2048), `--ctx-size` (4096~16384) 找到 4090 最佳配置
2. **KV Cache 预计算**：固定 system prompt 可利用 llama.cpp 的 `--prompt-cache` 缓存 KV，跳过重复计算
3. **FlashAttention**：`-DGGML_CUDA_FA_ALL_QUANTS=ON` 已在编译时启用，确认生效
4. **transformers + GPU 直连方案**：作为 Plan B，不走 llama.cpp，直接 HF transformers + `device_map="cuda"` + FlashAttention-2

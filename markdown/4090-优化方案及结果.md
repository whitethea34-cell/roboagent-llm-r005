# RTX 4090 CUDA 推理优化 — 方案及结果报告

> 日期: 2026-05-11 | 硬件: RTX 4090 (WSL2 + Docker) | 状态: ✅ 已完成

---

## 一、概述

### 目标

将 RoboAgent 推理从 Docker CPU-only（ARM 镜像）迁移到原生 CUDA 方案，利用 RTX 4090 实现 10~20x 提速。

### 模型

| 模型 | 参数量 | 量化 | GGUF 大小 | 来源 |
|------|--------|------|-----------|------|
| Qwen3.5-2B | 2B | Q4_K_M | ~1.28 GB | `qwen3_5/Qwen3.5-2B-Q4_K_M.gguf` |
| RoboBrain2.5-4B | 4B | Q4_K_M | ~2.72 GB | `RoboBrain2.5-4B-GGUF/RoboBrain2.5-4B.Q4_K_M.gguf` |

> 注：RoboBrain 实际使用 2.5-4B 版本（而非原规划中的 2.0-7B），更轻量、速度更快。

### 新增文件

| 文件 | 用途 |
|------|------|
| `4090.Dockerfile` | CUDA 版 Docker 镜像（nvidia/cuda:12.4.0 基础镜像） |
| `docker-compose.4090.qwen35.yaml` | Qwen3.5-2B @ 4090 一键启动 (8080) |
| `docker-compose.4090.robobrain.yaml` | RoboBrain2.5-4B @ 4090 一键启动 (8081) |

## 三、架构对比

```
ARM Dockerfile (CPU, 原方案)         |  4090 CUDA Dockerfile (新方案)
─────────────────────────────────────┼─────────────────────────────────────
arm64v8/ubuntu:22.04                 |  nvidia/cuda:12.4.0-runtime-ubuntu22.04
-DGGML_CUDA=OFF                      |  -DGGML_CUDA=ON
                                     |  -DGGML_CUDA_F16=ON
                                     |  -DGGML_CUDA_FA_ALL_QUANTS=ON
无 GPU 资源                          |  deploy.resources.reservations.devices: nvidia
--threads 4 (CPU only)               |  --threads 4 + --n-gpu-layers 99

```

## 四、部署步骤

### 一键部署

```bash
cd llm-r005

# 1. 构建 CUDA 镜像（仅首次，~10min）
docker build -t roboagent:4090-cuda -f 4090.Dockerfile .

# 2. 启动两个模型
docker compose -f docker-compose.4090.qwen35.yaml up -d
docker compose -f docker-compose.4090.robobrain.yaml up -d

# 3. 验证
docker ps                    # 两个容器 running
nvidia-smi                   # 显存被占用（~7.8 GiB）
curl -s http://localhost:8080/health  # {"status":"ok"}
curl -s http://localhost:8081/health  # {"status":"ok"}
```

### API 调用

```bash
# Qwen3.5-2B
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3.5-2b","messages":[{"role":"user","content":"Hello"}]}'

# RoboBrain2.5-4B
curl http://localhost:8081/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"robobrain","messages":[{"role":"user","content":"Hello"}]}'
```

## 五、遇坑记录及修复

### 构建阶段

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | `libcuda.so` 链接失败 | `nvidia/cuda:12.4.0-devel` 镜像不含驱动库，但 `libggml-cuda.so` 需要链接 `libcuda.so` | 添加 `ln -sf /usr/local/cuda/lib64/stubs/libcuda.so /usr/local/cuda/lib64/libcuda.so` 以及 `libcuda.so.1` 版本 |
| 2 | `libcuda.so.1` 链接器找不到 | 符号链接只创建了 `libcuda.so`，但运行时需要 SONAME `libcuda.so.1` | 添加 `ln -sf` 为 `.1` 版本 + `-DCMAKE_EXE_LINKER_FLAGS` |

### 运行时阶段

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 3 | `libllama-common.so.0` 缺失 | Dockerfile 只复制了 `llama-server` 和 `llama-cli`，没有复制 `.so` 共享库 | 改为 `COPY --from=builder /src/llama.cpp/build/bin/ /app/` + `ENV LD_LIBRARY_PATH=/app` |
| 4 | `libgomp.so.1` 缺失 | CUDA runtime 镜像没有 OpenMP 运行时库 | 安装 `libgomp1` 包 |
| 5 | `--log-format` 参数错误 | 新版本 llama.cpp 移除了 `--log-format` 参数 | 删除该参数 |
| 6 | `--chat-template-kwargs` 废弃 | 新版本改用 `--reasoning on/off` | 替换为 `--reasoning off` |
| 7 | 模型文件符号链接不可达 | Docker 容器无法解析指向 WSL 路径的符号链接 (`/mnt/e/...`) | 在 docker-compose 中使用 `volumes` 直接挂载实际文件路径 |

## 六、后续优化方向

1. **KV Cache 预计算** — 利用 llama.cpp `--prompt-cache` 缓存固定 system prompt，跳过重复 prompt 处理
2. **批处理优化** — `--batch-size 1024` 已启用，可进一步调优至 2048
3. **FlashAttention** — `-DGGML_CUDA_FA_ALL_QUANTS=ON` 已在编译时启用
4. **并发测试** — 测试多个 slot 同时推理的场景（server 支持 n_slots 配置）
5. **transformers + GPU 直连方案** (Plan B) — 不走 llama.cpp，直接 HF transformers + `device_map="cuda"` + FlashAttention-2
